### Shared-logic audit — intentionally left separate (with reasons)
- `run_text_command` / `run_json_command` (external_commands) vs `BackgroundTaskRunner` (components/background): thread delivery vs subprocess execution — different responsibilities, both already single implementations; no overlap.
- `_download_file_stats` (scanner sync delegate) vs `DownloadScanner._download_file_stats` (downloads): deliberate sync-layer compatibility seam (`_sync_download_scanner` + tests pin it); the scanner-side method forwards.
- `_file_hash`/`_file_content_marker`/`_cached_file_hash` in scanner vs downloads: scanner versions exist solely for the one-argument-hook compatibility fallback tested by `test_cancellable_scan_keeps_one_argument_hash_hooks_compatible`; unifying would break that seam.
- Trash walk (`_directory_file_size`) vs downloads walk: different semantics (hidden-file skip, symlink rules, progress/cancel, stat dict); unifying changes behaviour.
- `format_bytes` (scanner) vs `Analyzer._format_bytes` (algo): different output formats by design.
- `_battery_resource` (scanner card) vs `battery_info` (algo report): different output shapes (card fields vs report lines).
- `cpu_percent(interval=0.1)` (algo) vs `interval=0.2` (scanner dashboard): different sampling intervals by design.
- Dialogs' generation/refresh guards (ProcessDialog vs StorageDialog): real UX-semantic differences (cancel message, results-kept, button roles).
- window queue+poll delivery vs `BackgroundTaskRunner` per-callback delivery: two architectures serving different callers (batch queue vs single widget.after); unifying is a redesign.
- `psutil`/`pynvml`/`send2trash` per-module `= None` fallbacks: required for per-module monkeypatch seams (tests patch module globals).
- `ScanCancelled("Process scan cancelled")` (scanner) vs `DOWNLOADS_SCAN_CANCELLED` (scan_support): distinct messages, distinct contexts; `check_cancelled` stays the shared primitive.
- `_RecycleBinInfo` (scanner) vs `_WindowsGuid`/`_WINDOWS_DOWNLOADS_GUID` (downloads): distinct ctypes structs for distinct Windows APIs; no shared logic.
- `process_safety.protected_process_pids` (lenient) vs `ProcessSafetyPolicy._protected_pid_snapshot` (fail-closed, returns `complete` flag): deliberately different contracts (documented in the module docstring).
