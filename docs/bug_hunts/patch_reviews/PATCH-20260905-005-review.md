### Structure decisions (evidence-based)

1. **Package location: `maintenance/components/`** (replaces the module). The prompt's example sketch (`system_analyzer/components/...`) is conditional on repo evidence; the repository evidence is unambiguous: the app's internal package is `maintenance/` (every import in app + tests uses `maintenance.*`), there is no `system_analyzer` package, and creating a new top-level package would either duplicate the interface or force moving the whole app (broad redesign, forbidden). `maintenance/components/` delivers the target structure — `__init__.py` as the stable interface + one module per responsibility — with a zero-churn import surface.
2. **No artificial cpu/memory/storage/network/sensors modules**: those responsibilities live in `SystemScanner` (`maintenance/scanner.py`), not in the components file; creating them would be exactly the artificial duplication the prompt forbids, and moving them would broadly redesign the scanners. Scanner.py is 873 lines, under threshold, single responsibility (scan orchestration).
3. **`external_commands` stays `maintenance/external_commands.py`, outside the components package**: it is the generic executor shared by the scanner (single caller), has no component-specific knowledge (AST test enforces stdlib-only imports), and "shared generic execution ... stays outside individual hardware modules where it already belongs". Reviewed for shared code that belongs in it: nothing in the components implementation is subprocess execution (`BackgroundTaskRunner` is thread delivery, `check_cancelled` is a cancellation primitive) — nothing moves into it.
4. **Modules moved into the package (verbatim, sliced from the 004 files):** `scan_support.py`, `process_safety.py`, `downloads.py`; the 004 top-level files deleted (moved, not duplicated). Internal imports switched to relative (`from .scan_support import ...`).
5. **`components/__init__.py`** re-exports the full historical surface with `__all__` (20 names) — identical objects (`is`-identity tested).
