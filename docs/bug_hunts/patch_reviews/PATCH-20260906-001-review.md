## Patch summary

Implemented the bounded fix-forward plan:

- `NodeRegistry` now keeps promoted placeholders non-selectable until an
  operational context replaces them, removes the discovery candidate at
  promotion, rejects destructive capabilities during trust promotion, and
  updates known peer presence without recreating an untrusted candidate.
- `ScanCoordinator.cancel()` invalidates the active generation; `AppWindow`
  captures a dashboard scan's source node and provider before starting work.
- Component scans capture their source provider/scheduler/node; old-node
  completion releases only its source scheduler and cannot update the current
  node's UI/state.
- Discovery startup failure cleans up partial state and releases coordinator
  lifecycle ownership for retry.
- Dialog post-action rescans are bound to the original target; selector labels
  disambiguate duplicate display names; node switches reset unscanned cards and
  refresh the visible node label.

## Original bug / task evidence

- `NodeRegistry.promote_to_trusted()` left the candidate in `_discovered`, and
  `select()` rejected the same ID before checking its trusted context.
- A cancelled full scan retained its generation, so a queued Node A result
  could update Node B after selection changed.
- Component callbacks used current window mirrors rather than their source
  node/scheduler.
- Discovery startup failure occupied `AppCoordinator._discovery`, blocking a
  later retry.
