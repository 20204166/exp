## Patch summary

Second pass of the Prompt 2.1 audit (run after PATCH-20260905-002 landed). Remaining genuine duplication found and extracted:

- N1 decoding/output handling: the two 3-line `try: json.loads(...) except json.JSONDecodeError -> GPU unavailable` blocks in `_mac_gpu_details` (bare loads) and `_windows_gpu_details` (`stdout or "[]"` fallback) become `run_json_command(command, *, timeout_seconds, runner, empty_stdout_fallback)` in `maintenance/external_commands.py`, layered on `run_text_command`. Per-path empty-stdout semantics preserved via the `empty_stdout_fallback` parameter (mac: None; windows: "[]").
- N2 result/error representation: `f"{GPU_INFORMATION_UNAVAILABLE}: {error}"` repeated across 7 former sites → `SystemScanner._gpu_unavailable_message(error)` (5 direct call sites after the change; the 2 former JSON-decode error sites moved into `run_json_command`'s error return, whose message the callers render through the same helper — string output identical everywhere).
- N3 cancellation/scan support: `SystemScanner._protected_pids()` and `ProcessManager._protected_pids(psutil_module)` are identical `{0, 1, os.getpid()} + parent chain (tolerating NoSuchProcess/AccessDenied)` implementations → shared `components.protected_process_pids(psutil_module)`. `ProcessSafetyPolicy._protected_pid_snapshot` is deliberately NOT unified: it has stricter fail-closed semantics (any exception → incomplete → deny) and its own contract.
- N4 result representation: the "Downloads scan cancelled" literal is duplicated in `check_cancelled`'s default and StorageDialog's equality check → shared `components.DOWNLOADS_SCAN_CANCELLED` constant (message string unchanged).
- N5 scan lifecycle: `window.py` `_show_snapshot_for_generation`, `_show_error_for_generation`, and `_handle_scan_timeout` each repeat the stale-guard + `finish(generation)` + `_resolved_scan_generation` update sequence → extracted `_claim_scan_resolution(generation) -> bool` with identical operation order.

Rejected as not unified (report-only, unchanged from pass 1 plus):

- Window queue+poll delivery vs `BackgroundTaskRunner` per-callback `after(0)` delivery: two different architectures serving different callers; unifying is a redesign (task forbids).
- ProcessDialog vs StorageDialog generation/UX semantics: real behavioural differences (cancel message, results-kept behaviour, button roles).
- Scanner/actions lenient pid snapshot vs `ProcessSafetyPolicy` strict snapshot: intentional fail-closed difference.
- `SystemScanner._file_hash` vs `DownloadScanner._file_hash`: deliberate compatibility seam covered by `test_cancellable_scan_keeps_one_argument_hash_hooks_compatible`.
- Trash walk vs downloads walk; `format_bytes` vs `Analyzer._format_bytes`; `_psutil_value`/`_resource_with_fallback` (already single-file).
- components.py size/responsibility observation: ~1114 lines mixing eight concern groups; splitting would contradict the documented repo structure (AGENTS.md names components.py the extracted-seams home). Reported, not acted on.

Public behaviour: unchanged. Signatures: unchanged (all three GPU statics keep their names/arity; `_protected_pids` keeps its per-class signatures; window handlers keep names).
