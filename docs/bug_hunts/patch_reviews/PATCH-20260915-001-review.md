node details, and dashboard sharing. `AppWindow` owns one instance of each;
Nodes and Cluster pages receive optional opener callbacks with legacy fallbacks.

second `Tk()` root or changes to background work, authorization, persistence,

### Opposing Agent 2 — Repo-Truth Skeptic

**Verdict: supported findings, with the requested architectural controls otherwise verified.**

**Supported — P2: pairing dialog loses the advertised TLS fingerprint.**

- `maintenance/nodes.py:499-520` defines discovered candidates with both
  `identity_fingerprint` and `transport_fingerprint`.
- The prior pairing path displays the candidate's TLS value in
  `maintenance/ui/window_node_actions.py:47-59`, and the actual pairing path
  still requires and persists it at `:350-357` and `:381-392`.
- The new page projection at
  `maintenance/ui/window_supports/node_specs.py:14-29` copies only
  `identity_fingerprint` into `DiscoveredPeerSpec`; that spec has no transport
  field (`maintenance/ui/nodes_connections.py:68-80`).
- `window.py:585-593` therefore constructs `PairingDialogSpec` without a TLS
  value, while `maintenance/ui/pairing_dialog.py:59-67` renders
  `TLS fingerprint: Unavailable`. This is a user-visible loss of verification
  information on the new route. The authorization and TLS enforcement remain
  unchanged, so this does not prove a trust bypass.

**Supported — P2: port `0` behavior changed on the new manual-connection route.**

- The existing page-local form accepts `0 <= port <= 65535` at
  `maintenance/ui/nodes_connections.py:1076-1089`, and the controller retains
  the same accepted range in `maintenance/ui/window_node_actions.py:691-700`,
  called by `window.py:784-790`.
- The new `ConnectionDialog` instead rejects zero with `not 1 <= port <= 65535`
  at `maintenance/ui/connection_dialog.py:86-94`. Since
  `maintenance/ui/window_pages.py:165-196` routes the page's add action to
  this dialog, a previously accepted input is now rejected before the
  unchanged callback runs.

**Disproven / verified controls.**

- Exactly four additive dialog classes use injectable `tk.Toplevel` defaults:
  `maintenance/ui/connection_dialog.py:24-40`, `pairing_dialog.py:26-40`,
  `node_details_dialog.py:45-58`, and `sharing_dialog.py:24-38`. No added
  `Tk()` or `mainloop()` exists; `window.py:266` remains the sole application
  root creation site.
- Existing callback signatures and fallback behavior are preserved through
  `NodesConnectionsCallbacks` (`nodes_connections.py:40-65`) and
  `ClusterPageCallbacks` (`cluster_page.py:37-50`). The page adapters route to
  the new opener only when supplied and otherwise call the historical callback
  (`nodes_connections.py:415-419`, `:804-809`, `:1069-1089`; `cluster_page.py:342-355`).
- `AppWindow` owns one reference per workflow (`window.py:261-264`), rejects
  duplicate opens (`:565-567`, `:582-584`, `:597-599`, `:634-636`), and clears
  references on explicit close or `<Destroy>` (`:645-669`). The focused window
  tests cover construction/deduplication and close clearing at
  `tests/test_window_nodes.py:174-254`.
- The five-commit diff contains no changes to `maintenance/components`,
  `maintenance/preferences.py`, `maintenance/remote.py`, `maintenance/cluster.py`,
  `window_node_actions.py`, or `window_discovery.py`; the callback callees
  continue to own background/coordinator work, authorization, and persistence.

**Residual risk.**

- The focused command `scripts/run_tests.sh tests.test_node_toplevel_dialogs
  tests.test_nodes_connections_page tests.test_cluster_page tests.test_window_nodes -v`
  passed all 155 tests. Those tests do not assert TLS propagation through the

- The new dialogs do not close themselves after successful callback actions
  (`connection_dialog.py:97-99`, `pairing_dialog.py:78-79`, and
  `sharing_dialog.py:82-86`). This may be intentional, but leaves stale modal

## Main auditor rebuttal

The selected reviewer identified two genuine compatibility regressions. Both
were repaired with regression tests before final validation:

- `DiscoveredPeerSpec.transport_fingerprint` now preserves the candidate TLS
  fingerprint through `node_specs.py`, `window.py`, and `PairingDialogSpec`.
- `ConnectionDialog` now accepts the existing `0..65535` port range, including
  port `0`, while retaining validation for malformed and out-of-range values.
- Successful connection, pairing, and sharing callbacks close their owning
  dialog; local validation failures leave the connection dialog open.

The focused post-fix suite passed 164 tests. Source-level static checks passed
for changed files. The full suite's four failures are deployment checks against
the previously committed `1.5.9.0` wheel, which intentionally was not rebuilt
under the approved implementation scope; those failures do not indicate a
source callback, authorization, background, or Tk-root regression.
