### Opposing Agent 4 - External-Research Skeptic

**Review scope:** `TimerDelivery` extraction and `AppWindow` compatibility wrappers, with
focused review of `after`, `after_cancel`, callback lifecycle, exception handling,
and runtime typing assumptions.

**Repository evidence**

- `maintenance/ui/window_supports/timer_delivery.py:27-53` keeps the prior
  schedule lifecycle: it rejects scheduling while closing, registers one
  callback with `master.after`, tracks the returned ID, removes the ID before
  invoking the callback, and suppresses delivery after closing.
- `maintenance/ui/window_supports/timer_delivery.py:55-73` keeps the prior
  cancellation behavior, including clearing an ID when cancellation fails
  during shutdown. `cancel_all()` iterates over a tuple snapshot, so removing
  IDs during cancellation does not invalidate iteration.
- `window.py:3206-3230` delegates through thin wrappers and preserves the
  existing `_pending_after_ids` set and callback signatures. The lazy fallback
  is compatible with test instances constructed without `AppWindow.__init__`.
- `tests/test_window.py:123-156` covers scheduling failure, callback delivery,
  ID removal, and close-time cancellation. `tests/test_window_supports.py:151-200`
  covers the extracted implementation, including closing suppression,
  cancellation failure, and callback-failure logging for `invoke`.

**Official semantics checked**

- Python’s official Tkinter reference documents `Misc.after` as calling a
  function after a millisecond delay and returning an identifier to cancel the
  scheduling, and documents `after_cancel` as accepting that identifier:
  <https://docs.python.org/3/library/tkinter.html#universal-widget-methods>
  (see `after` and `after_cancel`). The CPython implementation additionally
  confirms that the callback form returns `self.tk.call('after', ms, name)`,
  whereas the no-callback sleep form is the form that returns `None`:
  <https://github.com/python/cpython/blob/3.14/Lib/tkinter/__init__.py>
- Tcl’s official `after` documentation says a delayed script is executed once,
  returns an identifier, and that cancelling an already-executed ID has no
  effect. This supports removing the ID before callback delivery and tolerating
  cancellation races during shutdown:
  <https://www.tcl-lang.org/man/tcl9.0/TclCmd/after.html>
- The Python Tkinter reference identifies `TclError` as the exception raised
  when a call into the Tcl interpreter fails:
  <https://docs.python.org/3/library/tkinter.html#tkinter.TclError>
  The extracted `RuntimeError`/`TclError` handling therefore preserves the
  existing application boundary for failed scheduling/cancellation; it does
  not claim to catch arbitrary callback exceptions. `TimerDelivery.invoke`
  retains the old explicit `Exception`-logging boundary at
  `timer_delivery.py:75-80`.

**Checked edge and conclusion**

The new `assert identifier is not None` at `timer_delivery.py:51` would reject
a non-conforming fake or a caller using Tkinter’s no-callback `after(ms)` form.
This application always supplies a callback (`timer_delivery.py:45`), and the
official callback-form contract returns an identifier; `tests/support/scheduling.py:42-45`
models that contract by returning `after#N`. No production or repository caller
passes the no-callback form through this helper. This is therefore not a
confirmed patch bug.

No external documentation claim contradicted repository behavior. No finding.
