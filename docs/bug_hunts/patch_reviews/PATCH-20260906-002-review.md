# PATCH-20260906-002 - mDNS discovery startup repair

## Mode and risk

BugGuard mode: Mode A - code-edit validation
Risk level: high
Validator threshold: full A4
Reason: Repair the installed mDNS backend's cross-platform startup path.

## Root cause and repair

`ZeroconfDiscoveryBackend.start()` read `Zeroconf.addresses`, but the installed
`zeroconf` 0.151.3 API exposes no such attribute. Startup therefore raised
`AttributeError`, which the fail-safe wrapper turned into a silent single-node
fallback. The backend now registers its presence-only, non-connectable service
without addresses. `ServiceInfo` supports omitted addresses, and peer discovery
uses the advertised TXT/SRV record rather than an address for this scope.

## Evidence

- Installed `zeroconf` 0.151.3: `hasattr(Zeroconf(), "addresses")` is false.
- Focused regression: `tests.test_network_discovery` verifies a current-shaped
  backend without that attribute starts and registers a service without an
  `addresses` argument.
- Real local start/stop with the source patch and `zeroconf` 0.151.3 passed.
