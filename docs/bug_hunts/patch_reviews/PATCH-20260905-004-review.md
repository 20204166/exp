# PATCH-20260905-004 — Mode A patch review (components/external_commands structure audit)

## Mode and risk

## Patch summary

Task: audit `maintenance/components.py` + `maintenance/external_commands.py` together and decide the internal package structure. No features, no behaviour change, no algorithm rewrites.

Audit findings:

- `components.py` was 1135 lines mixing nine responsibilities (shared types/constants/helpers, Windows ctypes structs, ProcessSafetyPolicy, DownloadsPathResolver, DownloadScanner, GpuDetector, BackgroundTaskRunner, ResourceFeature/Catalog, ScanCoordinator) — over the ~1000-line review threshold with genuinely unrelated responsibilities.
- `external_commands.py` is 77 lines, one responsibility, two pure functions, tuple results, single external caller (scanner.py). No README exists in the repo; `maintenance/__init__.py` already re-exports the top-level API; there is no package config (no pyproject/setup.py) and none is required.

Decisions:

1. **`external_commands` remains a single module** (not a subpackage, not segmented): segmenting 77 lines of two stateless functions into command-running/timeout/result-models modules would add ceremony without a maintainability win. Parsing isolation is enforced by a new AST-based test.
2. **`components.py` split by responsibility** into three new modules, with `components.py` kept as the stable compatibility facade (re-exports + `__all__`), so every historical `from maintenance.components import X` — app, tests, monkeypatch seams — keeps resolving to the identical object:
   - NEW `maintenance/scan_support.py` (38 lines, leaf): `ScanCancelled`, `DOWNLOADS_SCAN_CANCELLED`, `check_cancelled`, `require_psutil`, `ProgressCallback`, `ProgressTask`. Imports nothing from the package (no cycles).
   - NEW `maintenance/process_safety.py` (206 lines): `PROTECTED_PROCESS_NAMES`, `normalize_username`, `usernames_match`, `protected_process_pids`, `ProcessSafetyPolicy` (incl. its own chained-raise psutil loader, unchanged).
   - NEW `maintenance/downloads.py` (564 lines): `_WindowsGuid`, `_WINDOWS_DOWNLOADS_GUID`, `HashFingerprint`, `DownloadsPathResolver`, `DownloadScanner` — imports only `models`, `scan_support`, stdlib.
   - `components.py` (376 lines) keeps its own small seams (`GPU_INFORMATION_UNAVAILABLE`, `GpuDetector`, `BackgroundTaskRunner`, `ResourceFeature`, `ResourceFeatureCatalog`, `ScanCoordinator`) and re-exports all moved names.
3. **README/package config: no changes required** — no README exists (creation not required; install via `requirements.txt`, run via `python main.py`, tests via `python -m unittest discover -s tests` are all unchanged); `maintenance/__init__.py` untouched.

Implementation method: moved segments were sliced byte-exact from the original file (a first hand-retyped attempt produced formatting drift and was regenerated from exact slices before any components.py rewrite). Import fixes during the move: `Mapping`, `timezone`, `platform` added to `downloads.py` (all present in the original module namespace). Zero changes to `scanner.py`, `actions.py`, `dialogs.py`, `window.py`, `algo.py`, `models.py`, `__init__.py`, or any test import.
